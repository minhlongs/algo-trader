# Phase 4: BillingAgent

## Overview

Invoice generation, tier activation, revenue share calculation on NOWPayments IPN. Reuses existing payment + email infrastructure.

## Key Findings from Research

- NOWPayments webhook handler: `src/platform/workers/webhook-handlers.ts` (HMAC verification, status processing)
- Invoice generator: `src/platform/billing/invoice-generator.ts` — generates INV-YYYYMMDD-XXXX, stores to `data/invoices/`, emails via SendGrid
- Subscription lifecycle: `src/platform/billing/subscription-service.ts`
- Pricing tiers: `src/platform/billing/pricing-tiers.ts`
- Feature gate: `requireTier()` from `src/platform/middleware/feature-gate.ts`
- Revenue analytics: `src/platform/billing/revenue-analytics.ts`

## Anti-corruption Layer

BillingAgent is a **wrapper** around existing webhook handler — it does NOT replace `webhook-handlers.ts`. It adds: revenue share split + auto-invoice generation after the existing handler runs.

## Files to Create

- `src/agentic/billing-agent.ts` — Agent class orchestrating billing events

## Files to Modify

- `src/platform/workers/webhook-handlers.ts` — Add post-handler hook to emit billing events
- `src/platform/billing/invoice-generator.ts` — Add revenue share breakdown fields

## Event Flow

```
NOWPayments webhook (existing)
  1. webhook-handlers.ts verifies HMAC, sets tier
  2. → fires event: billing.charge.completed
  3. → BillingAgent listens:
     a. generateInvoice() → invoice-generator.ts (existing)
     b. updateRevenueShare() → revenue-analytics.ts (extend)
     c. notifyCustomer() → EmailService (existing, via invoice)
```

## Implementation Steps

1. Add event emitter pattern to `webhook-handlers.ts` after successful payment (use Node `EventEmitter` or simple callbacks)
2. Create `BillingAgent`:
   - `onPaymentCompleted(payload)` — hooks after webhook handler
   - `generateSplitInvoice(payment, tier)` — invoice + revenue share breakdown
   - `recordRevenueShare(payment)` — track provider earnings per strategy
3. Extend `Invoice` interface to include `revenueShare: ProviderShare[]`
4. Add integration test: mock NOWPayments webhook → verify invoice + share calc
5. Operator alert on high-value deals (ENTERPRISE ≥$299)

## Acceptance Criteria

- [ ] Payment confirmed → invoice auto-generated + emailed
- [ ] Revenue share correct for each tier
- [ ] No duplicate invoicing (idempotency via payment_id)
- [ ] Tests: payment flow mocks complete

## Risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Duplicate invoice on webhook retry | Medium | High | Idempotency: store `processedPaymentIds: Set<string>` in memory + file |
| Revenue share formula wrong | Low | Medium | Unit test expected amounts per tier |

## Rollback

Remove BillingAgent hooks from webhook-handlers.ts. Existing handler continues to work standalone. Invoices generated by original logic remain valid.
