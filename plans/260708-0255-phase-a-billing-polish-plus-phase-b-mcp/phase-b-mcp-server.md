# Phase B — MCP Server for Signal Discovery **Priority:** P1 (differentiation moat) | **Effort:** 1–2 weeks | **Depends on:** Phase A **Inputs:** brainstorm report, `src/platform/api/routes/signals-api-routes.ts`, `src/platform/middleware/signal-tier-resolver.ts` ## Overview Build a Model Context Protocol (MCP) stdio server that lets AI agents natively discover and consume trading signals. This is the agentic positioning identified as the competitive moat in ideation (260705-0025). ## MCP Contract | Concept | Algobot Surface | |---------|---------------| | **Tool** | `get_signals(tier, since, limit)`, `get_subscription_status()` | | **Resource** | Signal feed (paginated, `updatedAt`-tracked) | | **Auth** | Reuses existing Bearer API key → tier resolution | | **Transport** | stdio (local agent) + optional SSE (remote) | ## Files to Create 1. `src/platform/mcp/signal-mcp-server.ts` — MCP server implementation 2. `tests/unit/signal-mcp-server.test.ts` — tool contract + auth + tier tests ## Implementation Steps 1. **Scaffold stdio server:** Use `@modelcontextprotocol/sdk` `Server` class, stdio transport. Register tools and resources on `list_tools`/`list_resources` handlers. 2. **Wire `get_signals` tool:** Call the same cache-first logic as `GET /feed` (reuse `getCachedSignals` + `filterSignalsForTier`). Accept `tier`, `since`, `limit` params; return `{ data, count, tier, cached }` matching the REST response shape. 3. **Wire `get_subscription_status` tool:** Call `signalSubscriberRepo.getBySubscriberId(apiKey)`; return subscription existence + tier. 4. **Auth integration:** On each tool call, call `signal-tier-resolver`'s Bearer key extraction from the MCP session (stdio passes `Authorization` header via initial connection params). Reject with MCP error code if tier < SIGNALS_BASIC. 5. **Resource listing:** Expose `signal://feed/{tier}` URI scheme with pagination params encoded in query string. 6. **Tests:** - tool call returns filtered signals matching tier - invalid/missing API key returns auth error - SIGNALS_FREE tier rejected for SIGNALS_BASIC-required tool - response shape matches documented contract ## Touches 1. `src/platform/mcp/signal-mcp-server.ts` (new) 2. `tests/unit/signal-mcp-server.test.ts` (new) 3. `src/platform/middleware/signal-tier-resolver.ts` (read, may export helper) 4. `docs/api-reference-v2.md` — add MCP section ## Todo Checklist - [ ] Add `@modelcontextprotocol/sdk` dependency - [ ] Create `signal-mcp-server.ts` with stdio transport - [ ] Implement `get_signals` tool - [ ] Implement `get_subscription_status` tool - [ ] Register `signal://feed/{tier}` resource - [ ] Wire auth via signal-tier-resolver - [ ] Write unit tests (contract + auth + tier) - [ ] Add MCP section to `api-reference-v2.md` - [ ] Verify agent connects and calls tools via local MCP client ## Risk Assessment | Risk | Likelihood | Mitigation | |------|-----------|-----------| | SDK version mismatch / breaking changes | Low | Pin exact version; read SDK changelog if installing major version | | No existing MCP test fixtures in repo | Medium | Write minimal mock transport for tests, don't over-invest in fixtures | | Auth model mismatch (stdio vs HTTP Bearer) | Low | Pass API key in MCP initialization params; test the handshake path | ## Rollback Delete new files, remove dep from package.json.
