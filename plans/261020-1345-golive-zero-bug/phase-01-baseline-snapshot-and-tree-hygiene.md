## Overview

- **Goal:** produce an immutable, reproducible record of the exact local state the go-live work starts from, and reduce the dirty tree to a known, committable delta.

## Key Insights
- The tree carries **65 changed files** from a completed-but-uncommitted deep-modularization wave. A go-live diff is unreadable (and un-reviewable) against that background.
- Live production is at SHA `bca78f2e` (`fix: restore TS-clean state on fix/migration-026-nested-aggregate`), local `HEAD` is `5e263d30`. Production is therefore running a **known-ancestor** commit, not current `main` — expect a large deploy delta regardless.
- Quality gates currently pass, so there is no "fix the build first" step. Phase 01 only *records* that fact.

## Requirements
- Capture the FULL `git status --porcelain` output and a diffstat to a file under the plan directory.
- Record live/remote vs local SHA.
- Run and record all four static gates (typecheck, quality-baseline, unit suite, lint) with exit codes.
- Produce a baseline "known-state" markdown that Phase 08 appends to.

## Implementation Steps
1. Create the plan's `evidence/` directory.
2. Generate `evidence/baseline-snapshot.md` from one command chain, appending:
   - `date -u`, `git rev-parse HEAD`, `git rev-parse --abbrev-ref HEAD`
   - live SHA via `curl -sf https://api.cashclaw.cc/api/version`
   - `git status --porcelain` (unabridged, 65 lines is acceptable as evidence)
   - `git diff --stat` tail
   - exit codes of the four commands below
3. Run the four gates and record results:
   ```bash
   npx tsc --noEmit                                        # expect 0
   node scripts/check-quality-baseline.mjs --quality        # expect 5/5 PASS
   npx vitest run                                          # expect 17122 pass / 11 skip
   npm run lint                                            # expect 0 errors, 149 warnings
   ```
4. **Decision gate (user):** commit the 65-file modularization delta on branch `feat/triad-apex-deep-refactor-wave180-182`, or keep it uncommitted and filter it out of the go-live diff. Default recommendation: commit first — a go-live commit should contain only go-live changes.
5. Record the raw `curl` probe table for the API surface (already in the scout report; re-capture into `evidence/probe-baseline.txt`).

## Risk Assessment
| Risk | Impact | Mitigation |
|------|--------|------------|
| Committing 65 unrelated files muddies go-live history | Medium | Commit as ONE clearly-scoped commit before go-live work begins, so the go-live diff is clean |
| Environment differences mask a real gate failure | Low | Gate commands are the exact CI commands; CI runs the same |

## Security Considerations
- Snapshot contains no secrets. Do **not** `curl` any endpoint with an `Authorization` header and record it; the 401 on `/api/v1/shard/ring` must stay token-free.
- Attack surface: no new endpoints added in this phase.
