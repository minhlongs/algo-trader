## 2. D1 Migration Preflight, Ordering & Compatibility

Migrations in `migrations/poly-beta-d1/` MUST apply strictly in lexical order:

1. `0001-poly-beta-ledger.sql` — Core tenant-partitioned ledger (`beta_users`, `beta_sessions`, `beta_portfolios`, `beta_positions`, `beta_orders`, `beta_fills`, `beta_ledger_entries`, `beta_execution_logs`).
2. `0002-poly-beta-invite-redemptions.sql` — Single-use invite redemption table (`beta_invite_redemptions` keyed by `token_hash` SHA-256 digest).
3. `0003-poly-beta-feedback.sql` — Pilot feedback table (`beta_feedback`) using a distinct migration ID (`0003`).

### Forward / Backward Compatibility Analysis
- **`0002-poly-beta-invite-redemptions.sql`:** Purely additive (`CREATE TABLE IF NOT EXISTS beta_invite_redemptions` + `CREATE INDEX IF NOT EXISTS`). Non-destructive; safe to apply **before** Worker code rollout. Older Worker versions ignore the table.
- **`0003-poly-beta-feedback.sql`:** Distinct migration ID, purely additive (`CREATE TABLE IF NOT EXISTS`). Non-destructive; safe to apply **before** Worker code rollout.
- **Forward-Only D1 Constraint:** Cloudflare D1 migrations are forward-only and **cannot** be assumed auto-reversible. Never run destructive `DROP TABLE` / `ALTER TABLE DROP COLUMN` during an incident. Always capture a backup and verify D1 Time Travel bookmark before applying any migration.

### Preflight & Backup / Restore Commands
```bash
# 1. Export pre-migration SQL dump (remote D1)
npx wrangler d1 export poly-beta-db --remote --config wrangler.poly-beta.toml \
  --output /tmp/poly-beta-db-pre-migration-$(date -u +%Y%m%dT%H%M%SZ).sql

# 2. Record current D1 Time Travel bookmark
npx wrangler d1 time-travel info poly-beta-db --config wrangler.poly-beta.toml

# 3. Preview pending migrations (dry check)
npx wrangler d1 migrations list poly-beta-db --remote --config wrangler.poly-beta.toml

# 4. Apply migrations (ONLY after Founder Gate 2 approval)
npx wrangler d1 migrations apply poly-beta-db --remote --config wrangler.poly-beta.toml

# 5. Emergency restore via D1 Time Travel (by recorded bookmark or RFC3339 timestamp)
npx wrangler d1 time-travel restore poly-beta-db --bookmark <BOOKMARK_ID> --config wrangler.poly-beta.toml
```

## 3. Roll-Forward vs. Rollback Discipline

- **Schema-before-code / Code-before-drop:** Additive migrations (`0002`, `0003`) deploy before Worker code. If Worker code is rolled back, leave additive tables intact (no destructive down-migration).
- **Worker Rollback:**
  ```bash
  npx wrangler rollback --config wrangler.poly-beta.toml
  ```
- **Pages Rollback:** In Cloudflare Pages (`poly-beta-dashboard`), promote the prior verified deployment ID via Cloudflare Dashboard or `wrangler pages deployment list --project-name poly-beta-dashboard`.
- **Roll-Forward Preference:** For non-auth UI/copy defects, roll forward with a tested commit; for auth, tenant-isolation, or feed-freshness defects, disable first (Section 6), then rollback.

## 4. Secret Handling & Out-of-Band Invite Lifecycle

Secrets are **NEVER** committed to `wrangler.poly-beta.toml` or git. Manage exclusively via `wrangler secret put --config wrangler.poly-beta.toml`:
- `BETA_SIGNUP_ALLOWLIST` — Comma-separated allowlisted email(s). Unset = fail-closed (`403 SIGNUP_ALLOWLIST_REQUIRED`).
- `BETA_SIGNUP_INVITES` — Signed/hashed invite records generated by `scripts/poly-beta-issue-invite.mjs`. Unset = fail-closed (`403 INVITE_PROOF_UNAVAILABLE`).
- `POLY_BETA_SESSION_SECRET` — HMAC/session signing key.
- `POLY_BETA_PROXY_SECRET` — Internal proxy/service verification secret.

### Founder-Verified Out-of-Band Invite-Token Lifecycle
Because an invite token is a bearer credential until redeemed:
1. **Channel:** Deliver ONLY over a pre-verified end-to-end encrypted (E2EE) or direct verbal channel with `USER_001` — never in public chat, email plaintext, or git issues.
2. **Short TTL:** Issue with short expiry (`--ttl-hours 24` max).
3. **Immediate Redemption Confirmation:** Verify redemption row in `beta_invite_redemptions` (stores SHA-256 `token_hash`, never plaintext) immediately after `USER_001` signs up.
4. **Rotation / Disable:** Immediately clear or rotate `BETA_SIGNUP_INVITES` and `BETA_SIGNUP_ALLOWLIST` if a token is unused past TTL, leaked, or after `USER_001` onboarding completes.

## 5. Disable Modes, Kill-Switch & Data Preservation

| Control | Mechanism | Effect |
|---|---|---|
| **Signup Disable** | Set `SIGNUP_GATE_MODE="closed"` or clear `BETA_SIGNUP_ALLOWLIST` / `BETA_SIGNUP_INVITES` | Blocks all new signups (fail-closed) while preserving existing data |
| **Kill-Switch / Maintenance** | Set maintenance/kill flag via `scripts/poly-beta-disable.mjs` | Halts engine ticks and returns maintenance response on beta routes |
| **Session Revocation** | Delete rows from `beta_sessions` in `poly-beta-db` | Forces immediate re-authentication; stops active session access |
| **Account Deletion** | User-initiated `DELETE /api/beta/account` | Atomically purges all D1 tenant rows (`beta_sessions`, `beta_execution_logs`, `beta_ledger_entries`, `beta_fills`, `beta_orders`, `beta_positions`, `beta_portfolios`, `beta_users`) and calls `POST /purge` on `TenantPaperEngine` DO |

**Feedback Preservation Rule:** Incident disable / maintenance / signup-close **preserves** `beta_feedback` and audit ledger rows for post-mortem review. Full tenant purge occurs **only** on self-service `DELETE /api/beta/account` (or explicit Founder data-deletion request).

## 6. One-Command Disable Procedure

Use `scripts/poly-beta-disable.mjs` (targets `poly-beta-api` / `poly-beta-db` ONLY; zero impact on `algo-trader` production Worker):

```bash
# Dry run first (verifies target isolation and planned actions without mutating remote state)
node scripts/poly-beta-disable.mjs \
  --target poly-beta-api \
  --mode maintenance \
  --dry-run \
  --audit-log /tmp/poly-beta-disable-audit.jsonl

# Execute disable (requires explicit --confirm-disable flag)
node scripts/poly-beta-disable.mjs \
  --target poly-beta-api \
  --mode maintenance \
  --confirm-disable \
  --audit-log /tmp/poly-beta-disable-audit.jsonl
```

Supported `--mode` values: `signup-closed`, `maintenance`, `revoke-sessions`, `full-disable`. Confirm the audit log records target=`poly-beta-api`, UTC timestamp, and zero references to `algo-trader`.
