# Wasm Sandbox — Build & Usage

## Runtime choice

**Native WebAssembly API** (CF Workers built-in, Node ≥18, Bun, Deno).

No external Wasm runtime dependency (`@wasmer/wasi`, `wasmtime-js`, etc.).
Pure-compute kernels need no WASI syscalls, so the native API is sufficient
and keeps cold-start well under 100ms.

## Kernel: `spread-mean-reversion`

Source: `kernels/spread-mean-reversion.wat` (WebAssembly Text Format)
Binary: `kernels/spread-mean-reversion.wasm` (committed, ~271 bytes)

The `.wasm` binary is **committed to git** so no build step is needed at
deploy time. Regenerate only when the `.wat` source changes.

## Rebuilding the `.wasm` binary

Requires [wabt](https://github.com/WebAssembly/wabt) (`wat2wasm`).

```bash
# macOS (Homebrew)
brew install wabt

# Then from repo root:
bash src/sandbox/build-kernels.sh
```

The build script:

```bash
#!/usr/bin/env bash
# src/sandbox/build-kernels.sh
set -euo pipefail
KERNELS_DIR="$(dirname "$0")/kernels"
for wat in "$KERNELS_DIR"/*.wat; do
  out="${wat%.wat}.wasm"
  wat2wasm "$wat" -o "$out"
  echo "Built $out ($(wc -c < "$out") bytes)"
done
```

> If `wat2wasm` is unavailable, the committed binary remains valid.
> The binary was generated by hand-encoding the WAT logic in Node.js
> and validated with `WebAssembly.validate()`.

## Memory layout

```
Input region (bytes 0–39, written by host before compute()):
  0-7   f64 yesPrice
  8-15  f64 noPrice
  16-23 f64 prevEma    (0.0 = first call)
  24-31 f64 alpha
  32-39 f64 threshold

Output region (bytes 40–71, written by kernel after compute()):
  40-47 f64 spread
  48-55 f64 deviation
  56-63 f64 newEma
  64-67 i32 signal     (1 = trade signal, 0 = no signal)
  68-71 i32 side       (0 = yes-side, 1 = no-side)
```

## Security properties

- No WASI imports — kernel cannot access network, filesystem, or env vars
- Memory capped at 64 MB (1024 × 64KB pages)
- CPU capped at 500ms wall-clock via `AbortSignal` + `Promise.race`
- Output capped at 1 MB — oversized buffers are rejected
- Input validated via Zod before encoding
- Every invocation emits a tamper-evident audit record (input+output SHA-256)

## Adding a new kernel

1. Write `kernels/<strategy-name>.wat`
2. Run `build-kernels.sh` → commit the `.wasm`
3. Add the ID to `KernelId` in `wasm-runtime-loader.ts`
4. Add the filename to `KERNEL_FILENAMES` in the same file
5. Write a test in `tests/sandbox/`
